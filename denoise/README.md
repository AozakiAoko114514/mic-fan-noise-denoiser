# denoise —— 麦克风阵列实时降噪引擎（可逆、可回滚）

> **完整说明见仓库根目录的 `README.md`（中文）/ `README.en.md`（English）**；
> 一键启停用 `..\manager\manager.py`，Windows 上也可双击 `..\manager\start-all.cmd`。
> 本文件是降噪引擎的技术文档（设计依据、实测数据、算法参数、限制）。

针对**风扇噪声**（外置散热器 + i9-14900HX 自身风扇）做的实时降噪虚拟麦克风。

```
麦克风阵列 ──WASAPI采集──► 降噪DSP ──► Voicemeeter 虚拟输入 ──► 各应用（CS2/会议/直播）当麦克风用
```

## 为什么是 CPU 方案，而不是 NVIDIA Broadcast

| | 本方案（CPU） | NVIDIA Broadcast（GPU） |
|---|---|---|
| 对 CS2 帧率的影响 | **≈0**：进程绑到 16 个 E 核 + 低于普通优先级，CS2 几乎不用 E 核 | 占用独显并把显卡钉在 P0 状态，打游戏时是拿帧率换安静 |
| 实测开销 | 单线程 RTF ≈ **0.008**（约 125 倍实时），1 个 E 核的一小部分 | 几瓦 GPU，但会让独显保持唤醒 |
| 可调性 | 陷波频率/深度、过减因子、噪声偏差、门限全部可调 | 只有一个强度滑条 |
| 延迟 | 64 ms（算法）+ 声卡缓冲 | 几十毫秒 |

本机 i9-14900HX：24 核 / 32 线程（8 P + 16 E），音频 DSP 的算力需求对它来说是零头。

## 设计依据（来自本机实测，不是通用配方）

对 `mic-noise-test.wav` 的频谱分析结果：

* 噪声能量 **85% 落在 250–1000 Hz**，语音频段（300–3400 Hz）占 **93.6%**
  → 噪声与语音完全重叠，**低切/高通无效**（实测只降 0.1 dB），必须做谱减
* 存在清晰机械谐波族：**52.7 / 158.2 / 210.9 / 263.7 / 363.3 / 421.9 / 703.1 / 878.9 / 2068.4 / 2173.8 Hz**
  （基频 52.7 Hz ≈ 3160 RPM，363 Hz ≈ 7 叶风扇的叶片通过频率）
  → 用 ±18~30 Hz 的**窄带陷波精确挖掉**，避免通用 AI 降噪为了压窄峰而削薄整段人声
* 稳态性极好（帧间起伏 **4.1 dB**）→ 自适应噪声估计能学得很准，噪声门也好设

DSP 链：低频切除 → 10 个谐波陷波 → 滑动最小值噪声估计 → 维纳式过减谱减（帧间/频间增益平滑）→ 帧级软噪声门。

## 可调参数

```powershell
python live.py --run --bias 4.0 --over 3.0 --gate 6.0 --n-fft 2048
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--n-fft` | 4096 | 4096=64ms 延迟/11.7Hz 频点（默认）；2048=32ms/23.4Hz（陷波精度下降）；8192=128ms/5.9Hz |
| `--bias` | 2.5 | 噪声估计偏差补偿。**调大 = 压得更狠**（离线扫描：1.5→4.0 稳态压制 -13→-37 dB，而语音损伤指标不变） |
| `--over` | 2.5 | 过减因子 |
| `--gate` | 6.0 | 噪声门阈值（帧信噪比 dB）。说话间隙静音靠它 |
| `--gate-floor` | -16 | 门全关时的增益（dB） |
| `--no-gate` | — | 关闭噪声门（如果觉得有"吞字"感） |
| `--affinity` | 0xFFFF0000 | CPU 亲和性掩码，默认绑 16 个 E 核 |

## 验证对 CS2 帧率的影响

理论上影响≈0 的依据有两条，都可以自己验证：

1. **算力占用**：单线程 RTF≈0.008，即 1 秒音频只要 8 毫秒算力。跑起来后看任务管理器，python 进程 CPU 占用应为 **1% 上下**（一个 E 核的一小部分）。
2. **不抢 P 核**：进程亲和性掩码 `0xFFFF0000` 把它限制在 16 个 E 核上，CS2 主要跑 P 核。

实测步骤（约 3 分钟）：

```
1) CS2 控制台执行：  cl_showfps 1        （或开 NVIDIA App 的叠加层看帧率）
2) 进创意工坊地图/竞技模式，站着不动，记录稳定后的帧率 → 记为 FPS_A
3) 保持游戏运行，另开窗口启动：python live.py --run
4) 同样场景再记录帧率 → 记为 FPS_B
5) 对比 FPS_A 与 FPS_B；同时看任务管理器里 python 的 CPU 占比
```

预期：FPS 差值在测量噪声范围内（±1~2），python 占用 1% 上下。

**同时建议做对照实验**：把 NVIDIA Broadcast 也装上，用同样方法测一次。它占 GPU，在 CS2 这种场景下通常会看到更明显的帧率与显卡功耗变化——这样你就有了自己的数据来判断值不值得。

```powershell

# 或者直接删掉整个文件夹
```

停止运行的降噪进程后，麦克风立刻回到原始状态；各应用把麦克风改回 `麦克风阵列` 即可。

## 已知限制

1. **固定陷波依赖风扇转速稳定**。转速变化会让谐波移到陷波之外；兜底的是自适应谱减（它跟随任意稳态噪声）。
2. **拿不到阵列原始多通道**。本机 `麦克风阵列` 端点只对外暴露 2 通道（L/R 相关性 0.9167，基本是同一路处理结果），所以**做不到波束成形/声源定位**，这是硬件+驱动层锁死的。
3. **启动有 2 秒收敛期**（滑动最小值窗口）。这段时间相当于直通，不会伤语音。
4. **主观听感还需要你用耳朵确认**。目前的指标能证明"噪声压下去了、语音包络没被破坏"，但 musical noise（音乐噪声）和吞字感只能靠听。用 `--ab` 录一段带说话声的对比来听。
5. Voicemeeter 必须处于运行状态，虚拟通道才通；退出 Voicemeeter 后链路断开。
6. 独占模式（ASIO）的程序无法使用虚拟麦克风。
